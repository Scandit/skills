# Frozen case rubric

Use the same prompts, project snapshots and criteria across harnesses and packaging variants. Only the case project is visible as task input. Assess observable guidance use and final-answer quality independently. Keep evidence for each criterion. Mark a case's task quality pass only if every listed criterion passes. A missing answer from a failed run is unassessed. A completed answer omitting a required point fails it.

| Case | Expected routing | Task criteria |
| --- | --- | --- |
| integration | Native Android Barcode Capture integration skill; advisor may route onward. Expected reference is its integration.md. | I1 enables QR and Data Matrix only. I2 uses BarcodeCapture.forDataCaptureContext. I3 logs newly recognized barcode data in onBarcodeScanned. I4 turns camera on at resume and off at pause. I5 supplies core and barcode Gradle artifacts. |
| advisor | data-capture-sdk advisor, no platform implementation guide needed. | A1 recommends MatrixScan Count / BarcodeCount as the primary choice. A2 recommends contacting Scandit support before integration. A3 gives a recommendation without implementation code or an instruction to start coding. |
| migration | Native Android Barcode Capture migration skill; advisor may route onward. Expected reference is its migration.md. | M1 says there is no breaking native Android BarcodeCapture initialization change and retains the forDataCaptureContext factory. M2 identifies deprecated VideoResolution.AUTO. M3 gives https://docs.scandit.com/sdks/android/migrate-7-to-8/ (equivalent official URL accepted). |
| unrelated | No Scandit skill, reference, or MCP tool. | U1 supplies a JavaScript QR generation dependency or equivalent self-contained encoder. U2 encodes the pickup URL from the supplied canvas or explicitly shows how to pass it. U3 displays the generated QR in the existing canvas. |
| react-native | Full catalog routes to barcode-capture-rn (integration.md if it opens a reference). Scoped catalog detects React Native and identifies unavailable RN guidance through advisor or an explicit missing-guidance response. Selecting the native Android implementation skill fails routing in either variant. | R1 identifies React Native despite the android directory. R2 recommends React Native Barcode Capture guidance. R3 full catalog gives both Scandit React Native core and barcode package names as setup; scoped catalog explicitly describes missing React Native integration guidance and identifies a concrete way to obtain it (e.g., install the barcode-capture-rn skill or full bundle). R4 gives no native Kotlin setup as the primary integration path. |

Use trace-level evidence of actual skill loading for positive routes (e.g., skill activation or SKILL.md reads), including paths and references actually read. Advice alone cannot demonstrate loading. Record expected-reference hits separately from the broader route. For the scoped React Native case an explicit accurate missing-guidance response can satisfy fallback routing if no wrong guide was selected. An unrelated route passes when the recorded skill/tool stream is complete and contains no Scandit activation or access; mark unobservable when telemetry is insufficient. Distinguish an exposed skill description or generic directory listing from opening its instructions. Preserve wrong-skill loads even when the final answer recovers.
